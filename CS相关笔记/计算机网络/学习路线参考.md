## 总体路线（从能抓包→能写协议→能定位问题）

### 0）先把工具链装好（第 0 天）

- **Wireshark**（抓包分析核心）
    
- **tcpdump**（服务器上抓包）
    
- **curl** / **dig** / **nslookup** / **traceroute**（基础网络排查）
    
- **iperf3**（性能测试）
    
- **netcat(nc)**（“网络瑞士军刀”）
    
- （可选）**Docker**（搭环境很方便）
    

**实验 0.1：抓一次你访问网页的全流程包**

- 用浏览器打开任意网站，同时 Wireshark 过滤：
    
    - `dns` 看域名解析
        
    - `tcp` 看三次握手/四次挥手
        
    - `http` / `tls` 看应用层（HTTPS 看 TLS 握手）
        
- 目标：能说清楚“从输入网址到页面出现”发生了什么。

## 1）基础：TCP/IP & 分层思维（第 1 周）

你要建立“分层 + 封装 + 端到端”的直觉：**应用层请求 → 传输层端口/可靠性 → 网络层路由 → 链路层帧**。

**重点概念**

- IP、子网掩码、路由表、NAT
    
- MTU、分片（fragment）
    
- TCP 三次握手、窗口、重传、拥塞控制（知道大概机制即可）
    
- UDP 的特点与使用场景
    

**实验 1.1：手动看路由与连通**

- `ipconfig/ifconfig`、`route print/ip route`
    
- `ping` + `tracert/traceroute` 看路径
    
- 目标：知道“包下一跳去哪、为什么走这条路”。
    

**实验 1.2：MTU/分片验证**

- Windows：`ping -f -l 1472 8.8.8.8`（逐步调大/调小）
    
- Linux：`ping -M do -s 1472 8.8.8.8`
    
- 目标：理解“为什么某些链路会卡在某个包大小”。
    

---

## 2）传输层：把 TCP/UDP 玩明白（第 2~3 周）

**重点概念**

- TCP：可靠性、序号/确认号、滑动窗口、延迟确认、Nagle、TIME_WAIT
    
- UDP：无连接、丢包、乱序、适合实时/简单协议
    

**实验 2.1：用 nc 自己“造”客户端/服务端**

- 开两个终端：
    
    - 服务端：`nc -l 9000`
        
    - 客户端：`nc 127.0.0.1 9000`
        
- 再用 Wireshark 观察 TCP 建连/断开过程
    
- 目标：把“端口、连接、数据流”变成直觉。
    

**实验 2.2：复现 TIME_WAIT / 端口占用**

- 写个最小 TCP server（Python/Go/C 都行），快速启动/停止
    
- 观察：
    
    - Windows：`netstat -ano | findstr :9000`
        
    - Linux：`ss -antp | grep 9000`
        
- 目标：理解为什么“服务刚关又开会提示端口被占用”。
    

**实验 2.3：吞吐 vs 延迟（iperf3）**

- 同机/两机跑 `iperf3 -s` / `iperf3 -c <ip>`
    
- 调整并发、窗口等参数（先默认，再逐个改）
    
- 目标：知道“带宽跑不满”不是一句话能解释的。
    

---

## 3）应用层：HTTP/HTTPS、DNS（第 4~5 周）

这部分是最贴近开发/排障的，收益巨大。

**重点概念**

- DNS：递归/迭代、缓存、TTL、常见记录（A/AAAA/CNAME/TXT）
    
- HTTP/1.1 vs HTTP/2：连接复用、头部压缩、队头阻塞（概念）
    
- TLS：握手、证书链、SNI（知道抓包里哪里能看到）
    

**实验 3.1：DNS 全链路排查**

- `dig example.com` 看解析过程与 TTL
    
- 切换 DNS（系统/路由器/公共 DNS）对比结果
    
- 目标：知道“域名打不开”到底卡在哪一层。
    

**实验 3.2：抓 HTTPS 的 TLS 握手**

- Wireshark 过滤 `tls.handshake`
    
- 观察 ClientHello / ServerHello / 证书
    
- 目标：能解释“为什么证书错误会导致连接失败”。
    

**实验 3.3：手写一个最小 HTTP 服务**

- 支持：
    
    - `GET /health` 返回 200
        
    - 打印请求头（Host/User-Agent）
        
- 再用 `curl -v http://localhost:8080/health` 看请求细节
    
- 目标：把 HTTP 报文结构真正吃透。
    

---

## 4）网络工程与“真实世界问题”（第 6~7 周）

**重点概念**

- NAT / 端口映射
    
- 防火墙规则、入站/出站
    
- 代理、负载均衡（了解）
    
- QoS、丢包、抖动
    

**实验 4.1：复现“连得上但访问不了”**

- 本机防火墙阻断某端口，然后观察：
    
    - 客户端表现（超时/拒绝连接）
        
    - 抓包表现（SYN 重传 vs RST）
        
- 目标：学会通过现象判断是哪一类问题。
    

**实验 4.2：搭一个反向代理**

- 用 Nginx/Caddy 做反代到你的 HTTP 服务
    
- 观察 Host、X-Forwarded-For 等头变化
    
- 目标：理解微服务常见链路。
    

---

## 5）进阶方向任选（第 8 周以后）

看你偏哪条路：

- **系统/内核向**：深入 TCP 拥塞控制、零拷贝、eBPF、内核网络栈
    
- **安全向**：ARP 欺骗、DNS 污染、TLS 中间人、流量分析（合法合规环境）
    
- **分布式/后端向**：HTTP/2、gRPC、QUIC、服务发现、限流熔断
